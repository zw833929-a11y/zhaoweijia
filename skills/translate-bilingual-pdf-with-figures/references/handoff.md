## 3. 执行链

1. 渲染 PDF 全部页面，提取文本、文本块坐标和嵌入图片。
2. 结合页面截图重建阅读顺序，修复断词、连字和上标碎片。
3. 将标题、正文、方法、结果、讨论、声明、图注和参考文献整理成有序内容模型。
4. 对每个内容单元逐项翻译，保持术语、数字、单位、组别和引文一致。
5. 筛选完整主图；必要时重新编码为 Word 可接受的 RGB 图片。
6. 依据内容模型生成 DOCX：英文原文、译文、对应原图和双语图注交替排布。
7. 运行结构审计：内容覆盖、配对数量、图像数量、内联图片、参考文献连续性、占位符和页码域。
8. 将 DOCX 渲染成逐页图片，从首页检查到末页；修复后使用全新的渲染目录复查。

## 4. 验收标准

### 内容完整

- 标题、作者、单位、摘要、关键词、正文各节、致谢、声明、图注和参考文献均按范围纳入。
- 每个结构化单元有且只有一个对应译文，没有漏段、重段或错位。
- 参考文献总数、编号和顺序与原文一致。

### 翻译可靠

- 保留肯定/否定、升高/降低、促进/抑制、相关/因果以及可能性措辞。
- 数值、单位、温度、浓度、时间、样本量、统计符号、基因和蛋白名称保持不变。
- 缩写全篇一致，不凭空扩写。
- 原文存在可证实矛盾时不偷偷改写，忠实翻译并加中性译者注。

### 图文正确

- 每幅图与图号、面板标签和图注匹配。
- 图片为内联图片，不使用容易漂移的浮动锚点。
- 图片清晰、纵横比正常，并尽量与图注同页。

### 版式可交付

- 每一页均已实际渲染检查，不能只抽查首页或图页。
- 无中文方框、空白溢出页、重叠、裁切、孤立标题或残缺末页。
- 每次修订均渲染到新的空目录，避免旧页面混入。

## 5. 常见问题与处理

| 问题 | 原因 | 处理方式 |
|---|---|---|
| PDF 文本断词、乱段 | PDF 存储的是行和字形 | 结合坐标和截图重建语义段落 |
| 双栏内容交叉 | 默认提取顺序不等于阅读顺序 | 按页面几何分栏排序并人工核对 |
| 中文渲染为方框 | Office 渲染器缺少 CJK 字体 | 使用开放许可 CJK 字体并配置字体别名 |
| 封面后出现空白页 | 两种分页机制叠加 | 只保留一种分页方式并重新全页渲染 |
| 图片可查看但无法插入 Word | JFIF、CMYK 或色彩空间不兼容 | 解码后另存为 RGB PNG/JPEG |
| 精确字符串审计误报 | 上标/下标被拆成多个 DOCX run | 统一空白、连字和上标表示后再比对 |
| 修订后残留旧页面 | 重用了旧渲染目录 | 每版使用新的空目录 |
| 原文与图表矛盾 | 源论文自身不一致 | 保留原文并添加中性译者注 |
| 补充图在正文被引用但未提供 | 附件不完整 | 明确披露，不推测、不伪造 |

## 6. 下次复用

推荐调用：

> 使用 `$translate-bilingual-pdf-with-figures`，把这篇学术 PDF 全文逐段翻译为目标语言，每段双语对照，把所有原图插入对应位置，保留参考文献和科学符号，并输出完成结构审计和逐页视觉检查的 DOCX。

替换输入 PDF、目标语言、术语偏好、补充材料状态和版式要求即可；其余按以下链路执行：

资产盘点 → 内容建模 → 图号映射 → 科学翻译 → DOCX 生成 → 程序审计 → 全页渲染检查 → 交付报告。

## 7. 交接注意事项

- 开始前确认 supplement 是否齐全。
- 先建立内容模型再翻译，不要直接从 PDF 拼 Word。
- “PDF 内嵌图片对象数”不能替代“完整主图数”。
- 程序审计和视觉审计是两道独立门槛，二者都必须通过。
- 源论文有明显错误时记录证据和处理方式，不默默修改学术内容。
- 交付时报告页数、内容单元数、参考文献数、图数和逐页检查结果。
